## 3. 产品定义

### 3.1 Sprint 目标

1. **真实运行时可用**：把已存在的 hybrid search、feature flags、WriteService 和生命周期服务接入插件启动/界面路径，用户在真实 Obsidian 中能验证能力，而不只是单元测试可注入。
2. **运行时一致性与可恢复**：保证全量 rebuild、增量 Vault 事件和异步搜索在并发、失败、重试条件下不产生旧结果覆盖新状态；状态必须可见且不伪报成功。
3. **安全边界不退化**：所有新写入继续遵守白名单、scope/excludes、fiction/unknown proposal-only、before-hash/after-hash、审计和功能开关；Hermes 不可用时插件仍能启动和完成基本搜索。

### 3.2 用户故事

- As a **知识工作者**, I want to use semantic fallback from the Dashboard when keyword results are insufficient, so that I can find relevant notes beyond exact terms.
- As a **知识工作者**, I want the enabled feature flags to take effect in the running plugin, so that I can understand and control whether new search/organize/write behavior is active.
- As a **Vault 管理者**, I want Vault create/modify/delete/rename events and full rebuild to be serialized safely, so that the index never regresses to stale content.
- As a **用户**, I want rapid search input to show only the latest query result, so that an older asynchronous response cannot replace what I just searched for.
- As a **安全审查者**, I want every real write path to pass WriteService and an Obsidian WritePort adapter, so that direct or un-audited Vault mutation is impossible for the new pipeline.

## 5. 需求池

### P0：本 Sprint 必须完成

- **RT-001 Runtime composition**：插件启动时必须根据 settings 组装 `SearchService` 的 semantic port/config、`OrganizeService`、`WriteService` 及其 adapter；任何 adapter 不可用时必须降级或明确失败，不得阻塞插件启动。
- **RT-002 Obsidian WritePort adapter**：实现 Vault 读取与受控写入 adapter。新写入必须通过 `WriteService -> WritePort -> Obsidian adapter`；不得由 Dashboard/Agent 直接绕过服务层写 Vault。当前旧 AgentActionService 路径须明确为 legacy，不能被新写入管线复用为绕过入口。
- **RT-003 Real organize diff**：四类白名单动作必须只在实际缺失/需要规范化时生成 change；`after` 必须是预期内容，`diff` 必须非空且可读；无变化文件不生成 change。正文语义改写、删除、重排必须拒绝或 proposal-only。
- **RT-004 Runtime safety invariants**：保留 flags 默认关闭、scope/excludes、fiction/unknown proposal-only、before hash 冲突零写入、after hash、索引刷新失败状态和 request_id 审计。
- **RT-005 Desktop smoke flow**：真实 Obsidian 桌面验证插件启动、Dashboard、首次 rebuild、create/modify/delete/rename、搜索打开原文、rebuild 失败保留旧索引、Hermes 不可用降级。

### P1：本 Sprint 应完成

- **RT-101 Lifecycle coordinator**：为 rebuild 与增量事件建立统一串行协调或 generation/version guard；确保任意时序最终以最新 Vault 内容为准，失败保留可用旧索引并展示 failed 状态。
- **RT-102 Search latest-response guard**：Dashboard 为每次输入分配单调序号或 request token，只允许仍匹配当前 query/token 的响应更新结果区；关闭 view 后不得更新 DOM。
- **RT-103 Feature flags settings**：为 semantic search/fallback、organize 动作、new write pipeline、auto-apply 提供明确设置项；保存后新建/刷新 runtime 时生效，默认关闭并可一键回退。
- **RT-104 Platform decision**：在本阶段明确移动端策略。若继续 `isDesktopOnly: false`，必须移除/动态隔离 Node crypto 与 Buffer 并补移动端验证；否则将 manifest 明确改为 desktop-only，并同步文案与文档。
- **RT-105 Test gate**：将 QA 专项纳入默认测试或 CI；新增 lifecycle 并发、search race、runtime flags、adapter zero-write/conflict、organize diff 测试。

### P2：后续版本，不作为本 Sprint 交付承诺

- proposal 持久化、审批单条/批量、diff 审批 UI、双重审计持久化、pending-compensation、重启恢复、回滚。
- 研究 worker、外发审计、MemoryPublishService/Hermes Adapter 真实发布。
- 更复杂的 Dashboard 导航、移动端完整 UX 和主动巡检。

## 7. 本阶段验收标准

### P0 验收

1. 使用默认设置启动插件，插件、Dashboard 和旧快捷操作正常；Hermes/semantic adapter 不可用不导致启动失败。
2. 开启 semantic search/fallback 后，Dashboard 真实搜索能够在关键词不足时调用 semantic；keyword 命中始终优先，结果去重并标注来源；semantic 失败时关键词结果可用并显示 degraded 状态。
3. 新写入请求在 flags 关闭时对 Vault 零写入；开启后必须经 `WriteService -> WritePort -> Obsidian adapter`，白名单外动作、fiction/unknown 和 scope/excludes 违规均不写入。
4. 修改目标文件后 apply 必须以 `HASH_CONFLICT` 停止且原文不变；成功写入返回 after hash；索引刷新失败明确为 failed/pending，不得伪报完整成功。
5. 四类整理动作仅对真实缺失项生成非空 after/diff；无变化不生成变更；白名单外正文改写不生成可执行 change。
6. 真实 Obsidian 桌面完成启动 → rebuild → create/modify/delete/rename → 搜索 → 打开原文；失败 rebuild 仍能搜索上一份可用索引。

### P1 验收

1. 以任意交错顺序触发 rebuild 与增量事件，最终索引与 Vault 最新内容一致；旧 rebuild 结果不能覆盖较新事件。
2. 连续输入 `a`、`ab`、`abc` 并让响应乱序返回，结果区最终只显示 `abc`；关闭 Dashboard 后所有迟到响应不更新 DOM。
3. 设置页开关保存后 runtime composition 确实读取新值；重启后保持；关闭新开关不产生写入。
4. manifest 与 Node API 策略一致，并有对应平台验证或明确 desktop-only 声明。
5. `npm test`（含 QA 专项）、`npm run build`、`npm run lint`、`npx tsc --noEmit`、`git diff --check` 全通过；lint 既有 warning 必须分类记录，不能新增 error。

## 8. 风险与缓解

| 风险 | 级别 | 缓解 |
|---|---:|---|
| runtime 接入绕过 legacy 写路径导致安全边界分裂 | 高 | 仅允许新入口调用 WriteService；增加静态扫描和 adapter contract test |
| rebuild/增量竞态导致索引回退 | 高 | 全局协调器或 generation guard；补乱序事件测试；失败保留旧索引 |
| semantic adapter 不可用造成启动阻塞 | 高 | 可选注入、health/degraded 状态、关键词降级；默认关闭 |
| 整理 diff 生成器误改正文/未知 frontmatter | 高 | 仅白名单局部变更；解析异常不自动修复；before/after/hash 测试 |
| Node crypto 在移动端崩溃 | 高 | 本 Sprint 做平台决策；动态隔离或 desktop-only，不能维持冲突声明 |
| 写入后索引刷新失败造成用户误判 | 中 | 显示 refresh failed/pending；保留 Vault 写入审计并允许重试 |
| 现有未跟踪辅助文件被误提交 | 中 | 提交前显式排除 `.workbuddy/`、`overview.md`、本地 handoff 文件 |
| CI 只验证 build/lint，漏掉 QA | 中 | 将全部测试纳入 script/CI，报告默认测试总数与专项结果 |
