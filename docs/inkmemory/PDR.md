# 墨忆台产品需求文档（PDR）

> 版本：方案二基线（2026-08-07）  
> 状态：设计确认，待实现  
> 适用范围：现有 Obsidian 插件与 Agent Dashboard 的核心重构

## 1. 产品定位

墨忆台（Memory Workbench）是住在 Obsidian 内的工作台，用于管理用户的记忆库与工作内容。它保留现有 Obsidian 插件外壳和成熟 Dashboard，在其内部重构对话、检索、整理、研究和审计核心。

三者关系必须保持清晰：

- **Hermes**：用户已有/继续使用的主 Agent。
- **RAG + LLM Wiki**：为 Hermes 设计的动态记忆库，由 Vault 内容、索引和记忆管理流程组成；Hermes 使用这套动态记忆库读取记忆。
- **墨忆台**：管理记忆库和工作内容的 Obsidian 工作台，负责触发整理、研究、审核和可视化；墨忆台内部 Agent 仅执行工作台管理任务，不取代 Hermes。

墨忆台是否调用 Hermes CLI、以及具体同步协议，作为可插拔适配能力设计，不把 Hermes CLI 写成墨忆台固定运行依赖。

## 2. 目标与成功标准

### 2.1 目标

1. 在不破坏现有 Dashboard 使用习惯的前提下，统一聊天、搜索、整理、研究和审核入口。
2. 将 RAG + LLM Wiki 建成可重建、可追溯、兼容旧 Vault 的动态记忆层。
3. 通过低风险自动整理减少重复维护；高风险修改必须先 proposal → approve → apply。
4. 允许后台主动联网和研究，并保留外发内容与来源的审计证据。
5. 让 Hermes 能稳定读取动态记忆库，而不改变 Hermes 的主 Agent 定位。

### 2.2 成功标准（可验收）

- 现有插件可正常加载，已有 Dashboard 总览、订阅抓取、快捷操作和 Vault 扫描不回归。
- 用户可以从 Dashboard 或侧边栏完成：关键词搜索、语义兜底搜索、打开原笔记、查看 proposal、审批或拒绝、查看审计。
- 旧 Markdown、旧 frontmatter 和既有目录结构无需迁移即可被读取和索引。
- 自动整理只允许执行显式白名单动作：补充 frontmatter、补标签、补双向链接、格式标准化。
- 小说资料目录默认禁止自动写入，只能生成 proposal。
- proposal、审批记录和自动写入审计同时保存到 Vault 受保护目录与独立本地目录，插件重启后仍可恢复。
- 任何写入在 apply 前都校验当前文件 hash；冲突时停止写入并要求重新生成 proposal。
- Hermes 可读取已发布的动态记忆数据；墨忆台 Agent 不承担 Hermes 的对话主循环。

## 3. 用户与核心场景

### 3.1 主要用户

- **知识工作者**：希望从旧笔记中快速找到上下文，并让系统处理重复的元数据维护。
- **研究/写作用户**：需要后台联网收集资料，但希望来源、时间和外发范围可追溯。
- **小说创作者**：需要整理人物、设定和情节资料，但不接受系统直接改写小说资料。
- **Hermes 使用者**：希望 Hermes 继续使用动态记忆库，不被工作台替代。

### 3.2 关键流程

1. **检索**：输入查询 → 关键词优先（FTS5/标题/路径/frontmatter）→ 无足够结果时语义搜索兜底 → 展示命中片段与原文打开入口。
2. **自动整理**：扫描选定范围 → 识别白名单低风险问题 → 展示摘要 → 自动 apply → 更新索引与审计。
3. **高风险修改**：生成 proposal（diff、原因、目标文件、hash）→ 用户 approve/reject → apply 前再次读取和校验 hash → 原子写入。
4. **研究**：后台联网 → 记录 provider、URL、抓取时间、外发文件/片段 → 生成研究资料 → 正式区写入仍走配置的 proposal/审计规则。
5. **小说资料**：可分析和生成建议，但默认只生成 proposal，禁止自动写入小说资料目录。
6. **Hermes 同步**：索引发布/更新动态记忆快照 → Hermes 通过约定读取适配器消费 → 失败不影响 Vault 原文和墨忆台工作台。

## 4. 功能需求

### P0：核心可用性

- **FR-001 插件外壳复用**：保留现有 Obsidian 插件入口、命令、侧边栏和成熟 Dashboard 布局；核心服务以模块替换，不另起一套并行外壳。
- **FR-002 工作台导航**：至少提供总览、聊天/搜索、整理队列、研究、记忆库状态、审计和设置入口。
- **FR-003 关键词搜索**：优先使用现有 FTS5/元数据能力；结果展示标题、路径、命中字段、摘要和打开原笔记动作。
- **FR-004 语义兜底**：关键词结果不足、用户明确要求或配置触发时调用 bge-m3/兼容 embedding；索引不可用时降级为关键词搜索。
- **FR-005 旧格式兼容**：读取旧 frontmatter、未知字段和无 frontmatter 文件；不因索引字段缺失而修改原文。
- **FR-006 索引重建**：支持增量更新和全量重建；SQLite/向量索引均视为可重建派生数据，不作为事实源。

### P0：整理与安全写入

- **FR-010 白名单自动整理**：仅允许补充 frontmatter、补标签、补双向链接、格式标准化；每项动作均需可配置开关和目录范围。
- **FR-011 范围控制**：支持 Vault 全局、目录、标签、单文件和排除规则；小说资料目录默认仅 proposal。
- **FR-012 Proposal**：记录目标文件、原始 hash、变更 diff、动作类型、原因、模型/provider、创建时间和过期状态。
- **FR-013 审批**：支持单条、批量审批和拒绝；批量审批仍逐文件校验 hash，任何冲突单独失败。
- **FR-014 原子 apply**：读取当前文件 → 校验白名单与 hash → 写临时文件 → 原子替换 → 更新索引 → 写审计；任一步失败不得报告成功。
- **FR-015 回滚**：保留 apply 前后 hash 与必要的原文快照/补丁，使用户可以回滚自动整理结果。

### P0：持久审计与隐私

- **FR-020 双重持久化**：proposal、审批记录、自动写入审计同时写入 Vault 受保护目录和独立本地目录；使用 request_id 关联。
- **FR-021 审计查询**：按时间、文件、动作、操作者（用户/工作台 Agent/后台任务）、结果和 request_id 查询。
- **FR-022 联网外发记录**：后台联网允许发送相关全文，但必须记录发送的文件/片段、provider、模型、时间和请求关联；敏感内容识别和出库前提示不得省略。
- **FR-023 权限边界**：终端执行、写入范围、网络 provider 和模型均通过白名单配置；默认最小权限。

### P1：研究与记忆库管理

- **FR-030 后台研究**：支持后台主动联网和研究任务；任务可暂停、重试、取消，不能阻塞 Obsidian UI。
- **FR-031 研究入库**：保留来源、URL、抓取时间、引用片段、置信度和原始响应摘要；写入正式区遵循 proposal/审计策略。
- **FR-032 动态记忆发布**：从 Vault 与派生索引生成可供 Hermes 读取的记忆快照/查询接口；版本化并可回滚。
- **FR-033 Hermes 适配器**：提供读取/同步契约的适配层；适配器不可用时墨忆台仍可搜索和管理 Vault。

### P2：增强能力

- **FR-040** 提炼、merge 候选、link repair、trust 等现有 Hermes CLI 能力按模块逐步接入。
- **FR-041** 待办、订阅、GitHub 追踪和定时巡检在核心链路稳定后接入。
- **FR-042** 墨忆台 Agent 支持多轮工具调用，但工具权限受同一 proposal、范围和审计机制约束。

## 5. 非目标

- 不重写 Hermes，不把墨忆台 Agent 变成 Hermes 的替代品。
- 不把 SQLite、embedding 或模型输出当作唯一事实源。
- 不在 MVP 引入无边界的 `run_terminal`；如接入，必须采用命令白名单和独立审批。
- 不对小说资料执行默认自动写入。
- 不以“提升百分比”等无法验证的统计作为产品承诺。

## 6. 验收与质量门槛

- 兼容性：旧 Vault 在只读扫描、关键词搜索、索引重建中零破坏。
- 安全性：篡改文件后 apply 必须被 hash 冲突拦截；审计双写任一端失败要显示待补偿状态。
- 可恢复性：插件重启后待审批 proposal 和审计可恢复；索引删除后可从 Vault 全量重建。
- 性能：UI 线程不执行长时间联网、embedding 或全量扫描；任务状态可见。
- 可观测性：每次搜索、整理、联网、写入和 Hermes 同步均有 request_id。
- 回归：保留现有 Python 编译、Node 语法、Hermes 回归测试，并增加桌面点击流和冲突场景测试。

## 8. 已确认决策记录

| 决策 | 结论 |
|---|---|
| 产品方案 | 方案二：保留原 Obsidian 插件外壳和成熟 Dashboard，重构核心 |
| 系统关系 | RAG+LLM Wiki 是 Hermes 动态记忆库；Hermes 使用它；墨忆台管理它和工作内容 |
| Agent 边界 | 墨忆台 Agent 是工作台管理 Agent，不取代 Hermes |
| 搜索 | 关键词优先，语义搜索兜底 |
| 兼容 | 兼容旧 Vault/frontmatter，逐步扩展新字段 |
| 自动整理 | frontmatter、标签、双向链接、格式标准化可按范围自动写入 |
| 小说资料 | 默认仅 proposal，不自动写入 |
| 联网 | 允许后台主动联网和研究；可向外部模型发送相关全文 |
| 审计 | proposal、审批记录、自动写入审计双重持久保存 |
