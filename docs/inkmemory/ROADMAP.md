# 墨忆台产品路线图（ROADMAP）

> **文档性质：目标路线图/当前状态摘要。** 版本目标和验收标准是计划内容；表格状态只表示当前源码具备的基础能力，完整交付状态以 [`AGENT-HANDOFF-PROMPT.md`](AGENT-HANDOFF-PROMPT.md) 为准。
> 路线基线：方案二——保留现有源码仓库中的 Obsidian 插件外壳与成熟 Dashboard，逐步重构核心。  
> 版本目标不是一次性替换 Hermes：RAG + LLM Wiki 是 Hermes 的动态记忆库；Hermes 使用它；墨忆台是管理记忆库和工作内容的工作台；墨忆台 Agent 只做工作台管理/编排。

## 1. 路线原则

- 先保留用户熟悉的入口和 Dashboard，再替换底层服务。
- 先只读检索和可恢复索引，再开放受限自动写入。
- 关键词搜索优先，语义搜索兜底；embedding 不可用时不阻塞基本搜索。
- 自动写入仅限白名单动作：frontmatter、标签、双向链接、格式标准化，并受范围策略约束。
- 小说资料默认 proposal + 审批，不自动写入。
- 每个 proposal、审批和自动写入审计都双重持久保存。
- 每个版本都可独立验收、开关控制和回滚，不以未实现的 Hermes CLI 能力阻塞工作台。

## 3. MVP：工作台骨架与关键词检索

### 目标

在不破坏现有插件使用方式的前提下，提供墨忆台总览、搜索、记忆库状态和审计入口；先完成可靠读路径，不直接扩大写入权限。

### 范围

- 保留现有 Obsidian 插件入口、manifest、命令、侧边栏和成熟 Dashboard。
- 增加工作台导航：总览、聊天/搜索、整理队列、研究、记忆库状态、审计、设置。
- 复用 FTS5/标题/路径/frontmatter/标签能力，关键词搜索优先。
- 展示标题、路径、命中字段、摘要和打开原笔记动作。
- 兼容旧 Markdown、旧 frontmatter、未知字段和无 frontmatter 文件。
- 支持增量索引和从 Vault 全量重建。
- Workbench Agent 只开放 search/read/status 工具，不取代 Hermes，也不开放无限 terminal。
- 为未来语义搜索、proposal 和 Hermes 同步提供接口，但可以使用空适配器。

### 验收标准

- 旧插件可正常加载，成熟 Dashboard 总览、订阅抓取、快捷操作和 Vault 扫描无回归。
- 用户从 Dashboard 完成“关键词搜索 → 查看 snippet → 打开原笔记”。
- 旧 Vault 不迁移即可被读取和索引；删除派生索引后可重建。
- 索引和扫描不阻塞 Obsidian UI，失败任务有状态、错误和重试入口。
- Hermes 适配器不可用时，工作台基本搜索和管理仍可用。
- MVP 不执行自动写入；所有新代码通过开关可关闭并回到旧 Dashboard。

## 4. V0.2：混合检索与低风险自动整理

### 目标

在关键词检索稳定后，提供语义搜索兜底和可配置的低风险自动整理，减少重复元数据维护。

### 范围

- 关键词结果不足、用户明确要求或策略触发时调用 bge-m3/兼容 embedding。
- 结果注明 `keyword`/`semantic` 来源；embedding 不可用时降级关键词。
- OrganizeService 只允许：补 frontmatter、补标签、补双向链接、格式标准化。
- 支持 Vault 全局、目录、标签、单文件和排除规则。
- 个人记忆类笔记可按配置自动写入；研究资料可按配置自动写入正式区。
- 小说资料目录默认强制 proposal-only，即便同一整理规则在其他目录可自动执行。
- 预览 diff、逐文件结果、before/after hash 和索引刷新状态。

### 验收标准

- 给定相同查询，系统先展示关键词命中；不足时才调用语义搜索并标注来源。
- 索引/embedding 不可用时搜索仍可降级工作并提示状态。
- 白名单外的正文改写、删除、重排被拒绝。
- 受允许范围的四类整理可成功应用；小说资料没有自动落盘。
- 自动整理每次均有 request_id 和审计，即使尚未进入完整审批链路。

## 5. V0.3：Proposal、审批与安全写入

### 目标

把高风险和超出自动规则的变更纳入可追溯、可恢复的审批链路。

### 范围

- Proposal 保存目标路径、zone、动作、原始 hash、unified diff、原因、模型/provider、创建/过期时间和状态。
- 支持单条、批量审批和拒绝；批量逐文件校验。
- apply 前重新读取文件，校验路径白名单、目录范围、动作白名单、proposal 状态和 hash。
- 临时文件 + 原子替换；成功后刷新索引并双写审计。
- proposal、审批记录、自动写入审计保存到 Vault 受保护目录与独立本地目录。
- 双写失败进入 pending-compensation；支持补偿、回滚和审计查询。
- 插件重启后自动恢复待审批和待补偿队列。

### 验收标准

- 修改目标文件后审批 apply 必须被 hash 冲突拦截，原文不变。
- 审批成功能原子写入，写入失败不得显示成功。
- 每条 proposal 和审批记录在两端都有相同 request_id 与内容 hash。
- 用户可按时间、文件、动作、操作者、结果、request_id 查询审计。
- 回滚不覆盖用户在 apply 后的新修改；发生冲突时再次进入人工处理。
- 小说资料全程 proposal-only，除非用户显式改变策略并完成额外确认（默认仍禁止自动写入）。

## 6. V0.4：后台研究与 Hermes 动态记忆

### 目标

支持后台联网和研究，并把 RAG + LLM Wiki 的动态记忆以版本化方式提供给 Hermes。

### 范围

- 研究 worker 支持排队、暂停、取消、重试和失败恢复，不阻塞 UI。
- 记录 provider、模型、URL、抓取时间、引用片段、置信度、响应摘要和 request_id。
- 记录实际发送的文件/片段及其 hash；按网络策略执行敏感内容识别和出库前提示。
- 研究资料正式入库遵循 proposal/白名单策略；小说资料仍只 proposal。
- MemoryPublishService 生成版本化动态记忆快照或查询接口。
- HermesAdapter 提供发布、查询、健康检查和回滚；Hermes 只消费记忆，不获得工作台写入权限。
- Hermes CLI 是否存在不影响工作台运行，具体同步实现通过可替换适配器提供。

### 验收标准

- 后台研究在 Obsidian UI 中可见状态，暂停/重试/取消均生效。
- 每个网络请求能查到 provider、来源、外发范围和时间；研究资料可回溯到 URL 和引用。
- 研究导入正式区遵守目录策略，小说资料无自动写入。
- Hermes 能读取已发布版本；发布失败保留上一健康版本并可回滚。
- 墨忆台 Agent 不接管 Hermes 主对话和主推理，Hermes 适配器故障不阻塞搜索、审批和审计。

## 7. V0.5：主动巡检与工作内容编排

### 目标

在核心搜索、写入、审计和同步稳定后，让墨忆台持续维护记忆库和用户工作内容，同时保持人工可控。

### 范围

- 定时巡检索引积压、缺失 frontmatter、断链、过期 proposal、研究任务和待办。
- 将现有订阅抓取、GitHub 追踪、待办等成熟功能接入统一 TaskCoordinator。
- 主动研究建议、自动归档建议和批量 proposal；不允许后台任务越过范围和审批策略。
- Workbench Agent 支持多轮工具调用，但每个工具继承目录、provider、模型、request_id 和审批权限。
- 提供健康面板、失败补偿队列、审计报表、策略设置和动态记忆版本管理。

### 验收标准

- 定时任务可暂停、取消、重试，UI 始终可用。
- 巡检发现的问题生成明确建议或 proposal，不静默改写正文。
- 批量 proposal 可逐文件查看、审批、冲突隔离和回滚。
- 既有 Dashboard、订阅、GitHub、待办功能通过统一任务框架运行且无回归。
- Hermes 动态记忆发布、读取、健康检查和版本回滚均有审计证据。

## 8. 跨版本质量门槛

每个版本发布前必须通过：

- **兼容性**：旧 Vault/frontmatter/目录可读；旧插件入口与 Dashboard 不回归。
- **安全性**：路径和动作白名单、hash 冲突保护、原子写入、小说资料保护、敏感外发记录。
- **恢复性**：派生索引可重建；proposal/审批/审计重启可恢复；双写失败可补偿；文件和 Hermes 版本可回滚。
- **可观测性**：搜索、研究、模型调用、写入、审计和 Hermes 同步都有 request_id 和状态。
- **性能**：联网、embedding、全量扫描和索引重建不在 UI 线程执行。
- **测试**：保留现有 Python 编译、Node 语法、Hermes 回归测试，逐版本增加点击流、旧格式、冲突、重启恢复和降级测试。

## 9. 版本退出与回滚规则

- 任何 P0 安全门槛失败，版本保持开发状态，不推进下一版本。
- 所有新能力均受独立功能开关控制；异常时可逐项关闭并回到旧 Dashboard。
- 不删除旧索引、旧 proposal、旧审计或原始 Vault 文件作为“清理”。
- 新动态记忆以不可变版本发布；Hermes 异常时指向上一健康版本。
- 版本验收报告必须列出通过项、已知限制、回滚开关和待处理补偿记录。
